# ProFast 云同步

页面顶部的「云同步」打开统一的「云同步与备份」面板，使用 `shared/cloud-sync-ui.js`，与「这一年」和日语计时器共用样式。面板显示预填的同步服务地址（可修改）、专用密钥、复制/显示、连接状态和备份。密钥仅保存在当前浏览器；不同设备填写同一个专用密钥即可。它不是 Cloudflare 密码或 API Token。密钥持有者可读写云端记录，云端不提供端到端加密。公开代码和备份文件不包含密钥。

本地先保存，再后台自动同步。同步蛋白质摄入条目、断食开始/结束时间、蛋白质目标、断食模式和食材库；当前查看的模块只保存在本机。首次连接保留两边的独立记录，云端已有的修改优先于新设备的初始值；空白设备的默认目标和默认食材库不会覆盖其他设备已有的个性化设置。食材库整体同步以保留顺序，同一项的冲突采用最后修改版本；同时在两台设备修改食材库时，以最后修改的整份列表为准。

每条摄入记录独立合并，断食时间按日期和开始/结束字段分别合并。删除保留墓碑，避免旧设备把记录重新传回来。云端用数据库版本校验并发写入，冲突时重新读取合并。首次连接前的本地编辑也会保留为待同步修改。离线可用，联网、回到前台及页面停留时会自动补同步。同步失败不清空本地记录；断开连接也不删除两端数据。

原有 JSON 导入/导出继续可用，导入仍保持本机食材库，追加去重后的历史记录，并同步导入产生的修改。

## 服务

独立 Cloudflare Worker `health-tracker-sync` 和 D1 数据库 `health-tracker`，与其他应用隔离。接口地址为 `https://health-tracker-sync.zechengyu90.workers.dev/sync`。GET 读取版本和条目；PUT 以版本号条件提交合并条目。每个条目保存值、修改戳，删除保存 null。首次数据使用较低优先级的种子戳。

部署用的 `sync-worker/wrangler.toml`、`.dev.vars` 和本地缓存均已忽略，不提交公开仓库。更换账号时复制 `wrangler.example.toml` 为 `wrangler.toml`，创建独立 D1 并填入绑定，首次执行 `wrangler d1 execute health-tracker --remote --file=schema.sql`，部署 Worker，再通过 `wrangler secret put SYNC_KEY` 设置至少 24 字符的随机专用密钥。不要对已有数据库删除重建。重新部署保留现有 Secret 和数据。

## 验证

在仓库根目录运行：

```sh
node --test health-tracker/tests/*.mjs
python3 health-tracker/tests/browser.py
```

Node 测试使用内存 SQLite 验证双设备并发、离线合并、删除、断食字段、食材排序和目标、新设备、失败和请求期间的修改、断开、鉴权、CORS、输入验证，以及 Service Worker 更新和离线缓存隔离。

浏览器测试使用 web-access CDP Proxy、临时本地页面和模拟同步响应，验证顶部入口、密钥隐藏、记录合并、补传、删除、备份不带密钥、失败保留和 320/390/430px 布局。不使用真实密钥，不修改生产云端。
